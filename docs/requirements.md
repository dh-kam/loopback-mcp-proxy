# 요구사항

로컬 MCP 클라이언트가 원격 MCP 서버의 인증을 알 필요 없이 도구를 쓸 수 있게 하는 루프백 프록시다. 이 문서는 처음에 요청된 범위를 기준으로 정리한다.

## 목표

사용자는 Docker 이미지를 받아 컨테이너를 실행한다. 프록시는 루프백 주소에서 MCP 서버로 동작하고, 등록된 업스트림의 인증을 대신 처리한다. 프록시에 붙는 MCP 클라이언트는 자격 증명을 다루지 않는다.

## 사용자

- MCP 클라이언트. Cursor 등 로컬 프로세스가 프록시의 MCP 엔드포인트만 설정한다.
- 운영자. 웹 또는 TUI로 업스트림 MCP 서버를 등록하고 도구를 시험한다.

## 기능 요구사항

### 프록시

1. 프록시는 루프백 주소에서 MCP 서버로 수신한다.
2. 업스트림은 여러 개일 수 있다.
3. 클라이언트 요청은 해당하는 업스트림 MCP 호출로 전달된다.
4. 클라이언트 설정에는 업스트림 토큰, 비밀번호, OAuth 시크릿이 들어가지 않는다.

### 인증 대행

프록시가 업스트림에 대해 다음 인증을 대신한다.

| 방식 | 요구 |
| --- | --- |
| OAuth | 필요한 경우 액세스 토큰을 자동으로 갱신한다. |
| Bearer | `Authorization: Bearer` 헤더를 프록시가 붙인다. |
| Basic | 사용자 이름, 비밀번호, Realm을 다룬다. |
| 그 외 | 위와 같은 자격 증명을 프록시 설정으로 보관할 수 있어야 한다. |

자격 증명은 프록시만 저장한다. 클라이언트는 인증 실패와 갱신을 직접 수행하지 않는다.

### 관리 화면

1. 구현 언어는 Rust다.
2. 웹과 TUI 둘 다에서 MCP 서버를 추가, 삭제, 편집, 조회할 수 있다.
3. 웹은 React로 만든다.
4. 웹과 TUI는 프록시가 가진 서버 목록과 상태를 실시간으로 반영한다. 한쪽에서 바꾼 내용이 다른 쪽에 다시 조회하지 않아도 보여야 한다.
5. MCP 서버를 추가할 때는 마법사에서 입력한 값으로 실제 연결을 시도한다.
6. 웹에서 MCP tool을 Swagger처럼 다룬다. 인자를 입력하면 Rust 백엔드를 통해 해당 tool을 실행하고 결과를 보여 준다.

### 배포

1. 결과물은 Docker 이미지다.
2. 사용자는 이미지를 받아 컨테이너를 실행하는 것만으로 프록시와 웹 관리 화면을 쓴다.
3. TUI는 같은 이미지 안의 명령으로 실행할 수 있어야 한다.
4. Docker 밖에서도 릴리스 바이너리만으로 실행할 수 있어야 한다. Linux 릴리스는 공유 라이브러리 없이 실행되는 정적 바이너리다.
5. 플랫폼 구현 순서는 Linux가 먼저다. Windows와 macOS는 그 리눅스 릴리스 구현을 같은 구성으로 맞추는 후속 작업이다. 자세한 빌드 규칙은 `docs/platforms.md`에 둔다.

## 수용 기준

- `http://127.0.0.1:8080/mcp`에 인증 없이 MCP 클라이언트를 붙일 수 있다.
- Bearer, Basic, OAuth(갱신 포함)로 보호된 업스트림 tool을 그 클라이언트가 호출할 수 있다.
- 웹 마법사에서 저장 전에 연결 시험이 가능하다.
- 웹에서 tool 인자를 넣고 실행하면 업스트림 결과가 돌아온다.
- 웹과 TUI가 같은 서버 상태 변경을 실시간으로 본다.
- `docker compose up` 또는 동등한 컨테이너 실행으로 위 기능이 동작한다.
- Linux 릴리스 바이너리는 공유 libc 없이 그 파일만으로 실행된다.

## 범위 밖

요청에 포함되지 않은 항목이다.

- stdio 전송 업스트림
- 프록시 자체의 MCP 엔드포인트에 클라이언트 인증을 요구하는 것
- TUI 안에서의 tool 시험 실행. tool 실행 화면은 웹 요구사항이다.

## 후속

Windows와 macOS 릴리스는 배포 요구의 플랫폼 순서에 따라 Linux 릴리스 뒤에 맞춘다. 현재 수용 기준에는 넣지 않는다.
